# WeRead Knowledge MVP PRD

## 1. 产品定义

一款接入微信读书的桌面知识工具，将用户感兴趣的书籍、个人划线和想法蒸馏为可追溯、可编辑的知识卡片与思维导图。

首版只解决一个问题：**让用户把一本读过或正在读的书，整理成一张真正属于自己的知识地图。**

## 2. 目标用户

- 使用微信读书并有划线、写想法习惯的深度阅读者。
- 读完容易忘，希望重新整理一本书的人。
- 希望积累个人知识库，但不愿手工搬运笔记的人。

## 3. 核心价值

1. 自动同步：减少从微信读书复制、整理笔记的劳动。
2. 可信蒸馏：AI 生成的知识结论可以回溯到原始划线或想法。
3. 人机共编：AI 负责起草，用户负责修改、删除、确认和连接。
4. 图形理解：将线性笔记转成层次清晰的思维导图。

## 4. MVP 核心闭环

```text
连接微信读书
  → 从书架选择一本书
  → 同步目录、个人划线与想法
  → AI 生成单书知识档案
  → 展示为可编辑思维导图
  → 用户确认并保存
```

完成上述闭环，即视为 MVP 成立。

## 5. 功能范围

### 5.1 书架

目标：让用户找到需要整理的书。

功能：

- 连接微信读书 API。
- 展示书名、作者、封面、阅读进度和笔记数量。
- 支持按书名搜索。
- 点击一本书进入书籍工作台。

### 5.2 书籍工作台

目标：确认输入材料并发起蒸馏。

功能：

- 展示书籍信息和章节目录。
- 展示个人划线、想法及其所属章节。
- 支持选择全书或指定章节。
- 显示本次蒸馏将使用的材料数量。
- 点击“开始蒸馏”生成知识档案。

约束：

- 首版只基于微信读书 Skill 实际返回的目录、划线、想法和必要的公开信息进行蒸馏。
- 不把无法获取的完整正文假定为模型输入。

### 5.3 AI 蒸馏

目标：从阅读材料中提取结构化知识，而非生成泛泛摘要。

输出内容：

- 一句话主旨。
- 3–7 个核心主题。
- 每个主题下的关键观点、证据或案例。
- 用户自己的想法，且与作者观点明确区分。
- 3–5 个值得继续思考的问题。

生成规则：

- 每个正式观点至少绑定一条来源。
- 不确定或缺少来源的内容标为“AI 推断”，不得伪装成原书结论。
- 导图节点使用短标题，完整说明放在节点详情中。
- 优先保留用户写过想法的材料。

### 5.4 知识地图

目标：让用户查看、校正并保存蒸馏结果。

功能：

- 展示中心主题、一级主题和观点节点。
- 支持缩放、拖拽、展开和收起。
- 点击节点打开详情面板。
- 详情展示摘要、节点类型和原始来源。
- 支持编辑标题与说明、删除节点、移动节点。
- 支持“确认知识地图”并保存到本地。

节点类型：

- 书籍主旨
- 核心主题
- 作者观点
- 证据或案例
- 用户想法
- 待思考问题
- AI 推断

## 6. 页面结构

MVP 只包含四个主要界面：

| 页面 | 核心任务 | 主要操作 |
| --- | --- | --- |
| 初次连接 | 配置微信读书访问 | 输入并验证 API Key |
| 我的书架 | 选择一本书 | 搜索、打开书籍 |
| 书籍工作台 | 选择材料并蒸馏 | 查看笔记、选择章节、开始蒸馏 |
| 知识地图 | 校正和保存结果 | 查看来源、编辑、删除、确认 |

## 7. 关键数据对象

```ts
type Book = {
  id: string
  title: string
  author: string
  cover?: string
  readingProgress?: number
}

type Source = {
  id: string
  bookId: string
  chapterId?: string
  type: "highlight" | "user_note" | "public_info"
  text: string
  deepLink?: string
}

type KnowledgeNode = {
  id: string
  bookId: string
  parentId?: string
  type:
    | "book_thesis"
    | "theme"
    | "author_claim"
    | "evidence"
    | "user_idea"
    | "question"
    | "ai_inference"
  title: string
  detail: string
  sourceIds: string[]
  status: "draft" | "confirmed"
}
```

首版只需要树状父子关系，不引入复杂图数据库。

## 8. AI 输出协议

模型必须返回可校验的 JSON，而不是直接生成导图代码。

```json
{
  "thesis": {
    "title": "一句话主旨",
    "detail": "主旨说明",
    "sourceIds": ["source-1"]
  },
  "themes": [
    {
      "title": "核心主题",
      "detail": "主题说明",
      "sourceIds": ["source-1", "source-2"],
      "children": []
    }
  ],
  "questions": []
}
```

应用负责校验、保存和渲染该结构。来源不存在、节点超长或结构不合法时，应要求模型重试或标记失败。

## 9. 本地与隐私策略

- API Key 保存在系统安全凭据存储中，不写入普通配置文件。
- 书籍信息、笔记、知识节点和编辑结果默认仅保存在本地。
- 发给模型的数据应在蒸馏前向用户明确展示范围。
- MVP 不提供公开发布或社区分享。

## 10. 成功指标

首版重点验证是否有人愿意完成闭环，而不是追求用户规模。

- 首次连接成功率 ≥ 90%。
- 从选书到生成地图的任务完成率 ≥ 70%。
- 有来源的正式观点占比 = 100%。
- 用户对生成结果至少进行一次确认、编辑或删除的比例 ≥ 50%。
- 单本书在正常材料量下可在 3 分钟内得到结果。
- 体验用户中，愿意为第二本书再次使用的比例 ≥ 40%。

## 11. MVP 不做

- 不获取或破解微信读书完整书籍正文。
- 不做跨书知识图谱。
- 不做作者思想演变专题。
- 不支持视频、播客和网页蒸馏。
- 不做多人协作、社区、公开分享和关注系统。
- 不做自动复习、闪卡和考试系统。
- 不做复杂图数据库或知识本体。
- 不追求一键生成长篇讲书稿。
- 不同时支持多种导图布局，首版只提供一种稳定布局。

## 12. 验收标准

使用一个具有个人划线和想法的微信读书账户，用户能够：

1. 成功连接微信读书并看到书架。
2. 选择一本有笔记的书并看到章节、划线和想法。
3. 选择全书或若干章节发起蒸馏。
4. 获得包含主旨、主题、观点、用户想法和问题的知识地图。
5. 点击任一正式观点查看其原始来源。
6. 编辑或删除节点，并在重新打开应用后看到保存结果。
7. 清楚识别哪些内容来自作者、用户本人或 AI 推断。

以上七项全部通过，MVP 即可进入小范围用户测试。

## 13. 后续方向（不纳入首版）

MVP 验证后，第二阶段优先考虑跨书连接：当新书中的观点与旧知识存在印证、补充或冲突时，生成待用户确认的关系建议，而不是自动写入正式图谱。
