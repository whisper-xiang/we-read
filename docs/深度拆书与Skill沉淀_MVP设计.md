# 深度拆书 + Skill 沉淀:MVP 功能与交互设计

> 重心完全放在"深度拆书 + Skill 沉淀"上,小红书只是其中一个输出模板。

---

## 一、整体布局与交互框架

桌面端的核心优势是**多窗口对照**和**大空间操作**,MVP 的界面采用经典的三栏布局,充分利用屏幕空间。

- **左侧导航栏(20% 宽度)**:展示书架、拆书历史、Skill 库,支持搜索和标签筛选。
- **中间内容区(50% 宽度)**:核心工作区,展示书籍原文、划线笔记、AI 拆解结果。
- **右侧操作区(30% 宽度)**:展示生成的 Skill 卡片、笔记编辑器、导出选项。
- **顶部工具栏**:全局搜索、设置、API 配置入口。

---

## 二、核心功能模块设计

### 1. 配置与导入模块

这是用户进入产品的第一站,交互要尽可能简单,减少摩擦。

- **API 配置页**:首次启动时弹出引导页,用图文教程说明如何获取微信读书 API Key。输入框下方有"测试连接"按钮,验证成功后才允许进入主界面。配置信息**仅保存在本地**,界面上有明确的"本地加密存储"提示。
- **书架同步**:配置完成后,左侧导航栏自动展示用户的微信读书书架。支持按"最近阅读""全部书籍"筛选,点击某本书即可加载该书的划线笔记和想法。
- **本地文件导入**:如果用户不想接 API,支持直接拖拽本地的 Markdown、PDF、EPUB 文件到中间内容区,系统自动解析并进入拆书流程。

### 2. 拆书工作台(核心)

这是用户停留时间最长的页面,交互设计要围绕"深度阅读 + 结构化拆解"展开。

- **双栏对照视图**:左侧展示微信读书原文和划线笔记,右侧展示 AI 拆解结果。用户可以用鼠标拖拽调整两栏宽度,支持分屏对照。
- **一键拆解按钮**:在顶部工具栏放置醒目的"开始拆解"按钮。点击后,AI 会分析当前书籍的所有划线笔记,生成结构化的拆解报告。
- **结构化拆解展示**:拆解结果按以下维度组织,每个维度都支持折叠和展开:
  - **全书总揽**:一句话概括核心思想,提炼 3-5 个核心论点,用金字塔原理梳理支撑论据。
  - **章节地图**:按章节拆解核心内容,梳理逻辑结构,标注最具价值的章节。
  - **模型与框架**:自动识别书中的思维模型(如"三圈定位法"),用可视化卡片展示,支持导出为 Mermaid 图表。
  - **案例与故事库**:把书里的核心案例用 STAR 法则重新整理,方便日后写作时直接调用。
  - **术语表**:提取书中的专业术语和定义,生成可检索的术语卡片。
- **原文定位回溯**:点击 AI 拆解出的任何一个观点,右侧会高亮显示对应的原文划线位置,确保"拆书不瞎编"。这是建立用户信任的关键交互。
- **手动补充笔记**:在拆解结果旁边,用户可以直接添加自己的理解和补充笔记,系统会自动将人工笔记和 AI 拆解内容融合。

### 3. Skill 沉淀与卡片库

这是产品区别于普通拆书工具的核心,把书里的方法论变成可反复调用的"技能"。

- **Skill 生成**:在拆解完成后,AI 会自动识别书中的可执行方法论,生成 Skill 卡片。每张卡片包含:技能名称、适用场景、核心步骤、判断标准、原文出处。
- **卡片化管理**:左侧导航栏增加"Skill 库"入口,所有沉淀的 Skill 以卡片网格形式展示。支持按标签、书籍、类型筛选。
- **卡片编辑与完善**:点击任意 Skill 卡片,进入编辑模式。用户可以补充自己的使用经验、修改步骤、添加关联笔记。
- **关联与回溯**:每张 Skill 卡片都标注了来源书籍和原文位置,点击即可跳转到原始拆解页面。
- **导出与复用**:支持将 Skill 卡片导出为 Markdown、JSON 格式,方便导入 Notion 或 Obsidian,甚至让其他 AI Agent 在未来调用。

### 4. 输出与分发模块

拆书完成后,用户需要把成果输出到各个平台,小红书只是其中一种模板。

- **多模板输出**:在右侧操作区提供"导出"按钮,点击后弹出模板选择器,包含:
  - **小红书爆款笔记**:带情绪钩子的标题、Emoji 分段正文、话题标签。
  - **深度听书稿**:类似得到风格的口语化讲书稿。
  - **思维导图大纲**:直接导出为 Markdown 大纲,方便导入 XMind。
  - **记忆卡片**:把核心论点、思维框架、金句做成可打印的记忆卡片。
- **一键复制与导出**:选择模板后,AI 生成完整内容。用户可以直接"复制到剪贴板",或者"导出为 Markdown 文件"保存到本地。
- **预览模式**:在导出前,支持在右侧操作区预览最终效果,确认无误后再复制。

---

## 三、关键交互细节

- **拖拽交互**:支持把左侧的原文划线直接拖拽到右侧的笔记编辑器中,系统会自动生成引用标注。
- **快捷键支持**:桌面端必须支持快捷键,比如 `Ctrl/Cmd + D` 快速拆解、`Ctrl/Cmd + C` 复制内容、`Ctrl/Cmd + S` 保存当前状态。
- **状态提示**:AI 拆解过程中,中间内容区显示进度条和加载动画,避免用户以为卡死。
- **本地优先**:所有数据(API Key、拆解结果、Skill 卡片)都保存在本地,不依赖云端。用户随时可以关闭软件,下次打开时状态完整恢复。
- **空状态引导**:当用户还没有任何书籍或 Skill 时,界面显示友好的空状态提示,引导用户"添加第一本书"或"配置 API"。

---

## 四、MVP 功能边界

MVP 阶段必须克制,以下功能**绝对不要做**:

- **用户账号系统**:不需要注册登录,所有数据本地存储。
- **多端云同步**:先做单端桌面版,不要考虑手机和网页端同步。
- **社区与分享**:不需要做 Skill 市场或社区互动,先让个人用户用起来。
- **付费墙**:MVP 阶段免费开放所有功能,先验证用户价值。
- **自动发布到小红书**:小红书不开放个人 API,且存在违规风险,只能做到"生成并导出"。

---

## 五、核心用户流程

1. 用户打开 App → 配置微信读书 API Key(仅本地保存)。
2. 左侧书架自动同步,点击某本书。
3. 中间内容区展示该书的划线笔记,点击"开始拆解"。
4. AI 生成结构化拆解报告,用户对照原文阅读并补充笔记。
5. AI 自动识别并生成 Skill 卡片,用户编辑完善后保存到 Skill 库。
6. 点击"导出",选择小红书模板,复制文案或导出为文件。

---

这个设计把核心放在了"拆书"和"Skill 沉淀"上,小红书只是拆书后的一个自然输出结果。用户不仅是为了发一篇笔记,而是把书里的方法论真正变成自己的知识资产。
